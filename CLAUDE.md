## Documentation

Keep the built-in docs under `docs/` (served in-app, e.g. `docs/mcp.md`) in sync with the code.
**Always update the relevant docs whenever the API or tool surface changes, or for any change that
is not a straight patch/bugfix** — new or renamed/removed MCP tools or parameters, new endpoints,
config options, or behavior changes. Straight patches that don't alter documented behavior don't
require a docs update. This is in addition to updating `CHANGELOG.md` and `README.md` as part of
the release process.

## Wiki Skills

Before starting implementation tasks (writing code, adding new features, tests, builds, deployments, refactoring, release, compiling, documenting),
search the Gypsum wiki for relevant skills using `search_skills` with keywords matching
the language/framework and task type. Follow any matching skill instructions.
